# 016_3 Эксперимент I — Этап 1 — Требования к пространству состояний экспериментальной среды

## 1. Назначение

Экспериментальная среда является виртуальным пространством взаимодействия, в котором агент осуществляет экспедиции и получает эмпирический опыт посредством последовательного взаимодействия со средой.

Среда не является игрой в традиционном смысле.

Её назначение — предоставить агенту ограниченное, воспроизводимое и формально описываемое пространство возможностей, в котором:

- действия имеют последствия;
- последствия зависят от состояния среды;
- доступные ресурсы ограничены;
- часть информации непосредственно доступна агенту, а часть должна быть обнаружена;
- прошлое взаимодействие может изменять последующее поведение;
- накопленный опыт потенциально повышает эффективность последующих экспедиций.

Главным объектом исследования является не способность агента «выигрывать игру», а возможность формирования и использования эмпирического опыта.

---

## 2. Основной принцип

Среда должна создавать **контролируемую неопределённость**.

Слишком простая среда не создаёт пространства для формирования опыта:

> действие → очевидный результат.

Слишком сложная среда не позволяет установить причинные связи:

> слишком много переменных → невозможно определить, что именно было изучено.

Требуется промежуточная область сложности, в которой агент вынужден:

1. наблюдать;
2. выбирать;
3. получать результат;
4. сохранять информацию о результате;
5. использовать ранее полученную информацию при последующем выборе.

---

## 3. Пространство состояний

Среда представляет собой конечное дискретное пространство состояний.

Состояние в каждый момент времени определяется совокупностью переменных среды:

```text
S = {
    spatial_state,
    resource_state,
    temporal_state,
    discovered_state,
    environmental_state,
    expedition_state
}
```

Конкретный состав переменных должен быть минимальным: каждая переменная должна иметь экспериментальное назначение.

Среда не должна содержать переменных, не участвующих в формировании наблюдаемого результата.

---

## 4. Пространственная составляющая

Среда должна содержать дискретное пространство перемещений.

На первом этапе предпочтительно использовать двумерное поле.

Каждая позиция поля является состоянием пространственного компонента:

```text
(x, y)
```

Поле должно поддерживать:

- проходимые области;
- непроходимые области;
- объекты интереса;
- целевые области;
- неизвестные для агента области.

Размер поля является параметром эксперимента, а не фундаментальным свойством среды.

---

## 5. Ограниченное пространство действий

В каждом состоянии агенту предоставляется конечное множество допустимых действий.

На первом этапе количество базовых действий должно оставаться минимальным.

Предполагаемый базовый набор:

```text
MOVE_N
MOVE_S
MOVE_E
MOVE_W
SEARCH
```

Дополнительные действия не вводятся без экспериментальной необходимости.

Каждое действие должно иметь:

- стоимость;
- возможные непосредственные последствия;
- возможные отложенные последствия;
- условия допустимости.

Среда не должна подсказывать агенту, какое действие является оптимальным.

---

## 6. Два конкурирующих ограничения

Среда должна содержать два независимых ограничивающих ресурса.

### Энергия

Определяет возможность продолжать активное взаимодействие со средой.

### Время

Определяет ограниченность доступного количества шагов или временного окна экспедиции.

Оба ресурса должны одновременно влиять на возможность достижения цели.

Это создаёт необходимое пространство компромисса:

```text
исследовать больше
        ↕
сохранить ресурс
        ↕
достичь цели вовремя
```

Количество критериев, непосредственно определяющих исход экспедиции, должно оставаться ограниченным.

На первом этапе используются два основных конкурирующих ограничения.

---

## 7. Наблюдаемое и скрытое состояние

Не всё состояние среды должно быть непосредственно доступно агенту.

Необходимо различать:

```text
REAL STATE
     │
     ├── OBSERVABLE STATE
     │
     └── HIDDEN STATE
```

Агент получает только наблюдение, сформированное из текущего состояния среды.

Скрытая часть состояния может быть раскрыта:

- перемещением;
- исследованием;
- обнаружением объекта;
- возникновением события;
- накоплением опыта.

Это является необходимым условием возникновения эмпирического знания.

---

## 8. Действие как переход состояния

Среда должна быть детерминированной при фиксированном начальном состоянии и seed.

Основной механизм:

```text
(S, A) → S'
```

где:

- `S` — текущее состояние;
- `A` — действие агента;
- `S'` — новое состояние.

При одинаковых:

```text
initial_state
seed
action_sequence
```

результат должен быть полностью воспроизводим.

---

## 9. Последствия действий

Последствия должны быть не только непосредственными.

Среда должна поддерживать:

### Непосредственные последствия

Изменение состояния сразу после действия.

### Отложенные последствия

Изменение состояния, проявляющееся после нескольких последующих действий.

Это необходимо для формирования причинных связей, которые нельзя свести к простому правилу:

> действие X всегда немедленно даёт результат Y.

Отложенные последствия должны оставаться ограниченными и контролируемыми.

---

## 10. Необходимость исследования

Среда должна содержать информацию, которую невозможно получить исключительно из начального наблюдения.

Агент должен иметь возможность совершать действия, направленные не непосредственно на достижение цели, а на получение информации.

Таким действием на первом этапе является:

```text
SEARCH
```

Тем самым появляется фундаментальное различие:

```text
действие ради результата
        ↕
действие ради информации
```

Это различие является одним из ключевых механизмов формирования эмпирического опыта.

---

## 11. Экспедиция

Экспедиция является одной полной траекторией агента через пространство состояний.

```text
S0
 ↓
A0
 ↓
S1
 ↓
A1
 ↓
S2
 ↓
...
 ↓
Sn
```

Экспедиция начинается с начального состояния и завершается при наступлении терминального условия.

Терминальными состояниями могут быть:

```text
SUCCESS
FAILURE
TIMEOUT
RESOURCE_EXHAUSTED
```

Конкретный набор терминальных состояний является параметром эксперимента.

---

## 12. Цель

Среда должна иметь конечную цель, достижение которой возможно различными траекториями.

Цель не должна быть настолько очевидной, чтобы оптимальная последовательность действий следовала непосредственно из начального состояния.

При этом пространство решений должно оставаться ограниченным настолько, чтобы анализировать причинную связь:

```text
выбор
  ↓
траектория
  ↓
опыт
  ↓
результат
```

---

## 13. Генерация среды

Начальное состояние среды должно генерироваться процедурно.

Генератор должен использовать seed.

Seed является частью экспериментального состояния и должен сохраняться вместе с результатами экспедиции.

Генерация должна позволять управлять:

- размером поля;
- расположением препятствий;
- расположением объектов;
- сложностью маршрутов;
- распределением информационно значимых событий.

Генератор не должен создавать заведомо оптимальную или специально обучающую траекторию.

---

## 14. Независимость среды от агента

Среда не должна содержать модели интеллекта агента.

Она не должна:

- оценивать намерения агента;
- выбирать за него действия;
- корректировать его поведение;
- специально подстраиваться под его стратегию;
- хранить знания, предназначенные для помощи агенту.

Среда предоставляет:

```text
наблюдение → возможности → последствия
```

Агент самостоятельно формирует:

```text
интерпретацию → выбор → опыт
```

---

## 15. Опыт как результат взаимодействия

Среда должна обеспечивать возможность восстановить опыт агента из последовательности взаимодействий.

Минимальная единица опыта:

```text
Observation
    +
Action
    +
Consequence
    +
Resulting State
```

То есть:

```text
O_t + A_t → O_(t+1)
```

Среда не обязана самостоятельно создавать долговременную память агента.

Однако она должна предоставлять полный материал, необходимый для её формирования внешним когнитивным контуром.

---

## 16. Полная регистрация

Каждый шаг экспедиции должен регистрироваться.

Минимальная запись:

```text
step
state
observation
available_actions
action
immediate_result
new_state
resource_state
terminal_state
```

Журнал должен позволять:

- полностью воспроизвести экспедицию;
- восстановить траекторию;
- сравнивать экспедиции;
- анализировать изменение поведения;
- находить причинные связи между действиями и результатами.

---

## 17. Аналитическая визуализация

Графическая визуализация игрового мира не является обязательной частью экспериментальной среды.

Интерфейс должен быть ориентирован прежде всего на машинное взаимодействие и анализ данных.

Визуализация, если потребуется, является внешним аналитическим инструментом.

Она должна строиться на основе журнала эксперимента и не изменять саму среду.

---

## 18. Режимы эксперимента

Среда должна поддерживать несколько типов экспедиций при сохранении единого механизма переходов.

Минимально необходимы:

### Режим A — первичное взаимодействие

Агент не имеет релевантного прошлого опыта.

### Режим B — повторное взаимодействие

Агент получает возможность использовать опыт предыдущих экспедиций.

### Режим C — перенос

Изменяется часть условий среды при сохранении определённого класса закономерностей.

Цель режима C — проверить, является ли приобретённый опыт конкретной последовательностью действий или способен становиться более общим знанием.

---

## 19. Основное требование к сложности

Сложность среды должна быть параметризуемой.

Необходимо иметь возможность независимо изменять:

- пространственную сложность;
- стоимость исследования;
- стоимость перемещения;
- ограниченность времени;
- ограниченность энергии;
- количество скрытой информации;
- частоту событий;
- степень отложенности последствий.

Это позволит искать область параметров, в которой формирование эмпирического опыта становится наблюдаемым.

---

## 20. Критерий пригодности среды

Среда считается пригодной для эксперимента, если она одновременно обеспечивает:

1. конечное пространство действий;
2. неоднозначность выбора;
3. ограниченность ресурсов;
4. необходимость исследования;
5. последствия действий;
6. возможность ошибочного выбора;
7. возможность получения новой информации;
8. возможность повторного использования полученной информации;
9. воспроизводимость;
10. возможность количественного анализа поведения.

Главный критерий:

> **предыдущий опыт должен потенциально изменять качество последующего выбора.**

При этом сама среда не должна гарантировать, что такое изменение произойдёт.

---

## 21. Что среда не должна проверять

На первом этапе экспериментальная среда не предназначена для проверки:

- языковых способностей;
- визуального восприятия;
- пространственной визуализации;
- сложного планирования;
- скорости вычислений;
- способности решать внешние головоломки;
- качества конкретной LLM.

Среда должна минимизировать влияние этих факторов настолько, насколько это возможно.

---

## 22. Предельная архитектурная формула

Экспериментальная среда должна сводиться к следующему циклу:

```text
        STATE
          │
          ▼
     OBSERVATION
          │
          ▼
        AGENT
          │
          ▼
        ACTION
          │
          ▼
   STATE TRANSITION
          │
          ▼
     CONSEQUENCE
          │
          ▼
     NEW STATE
          │
          └──────────────┐
                         │
                         ▼
                    EXPEDITION
                         │
                         ▼
                      RESULT
```

При этом:

```text
Environment = поле возможностей

Agent = источник выбора

Experience = результат взаимодействия

Memory = механизм сохранения и рекультивации опыта

Experiment = сравнение траекторий поведения
```
---

## 23. Физическая и сервисная изоляция экспериментальной среды

Экспериментальная среда должна существовать как отдельный программный процесс и не должна быть частью когнитивного процесса агента.

Предпочтительный способ развёртывания — отдельный Docker-контейнер.

Это является не требованием к конкретной технологии реализации, а способом обеспечить принципиальное разделение:

```text
┌──────────────────────┐
│   Cognitive System   │
│                      │
│  LLM                 │
│  memory              │
│  retrieval           │
│  reflection          │
│  decision            │
└──────────┬───────────┘
           │
           │ observation / action
           │
           ▼
┌──────────────────────┐
│ Experimental         │
│ Environment Service  │
│                      │
│ state                │
│ rules                │
│ transitions          │
│ generation           │
│ journal              │
└──────────────────────┘
```

Среда не должна иметь прямого доступа к внутреннему состоянию когнитивной системы.

Когнитивная система не должна иметь прямого доступа к внутреннему состоянию среды, за исключением данных, предусмотренных контрактом наблюдения.

---

### 23.1. Среда как независимый сервис

Environment Service отвечает исключительно за:

* создание и хранение состояния экспедиции;
* генерацию конфигурации;
* предоставление наблюдения;
* предоставление допустимых действий;
* применение действий;
* вычисление последствий;
* переход состояния;
* определение терминального состояния;
* журналирование взаимодействия.

Он не отвечает за:

* принятие решений;
* интерпретацию опыта;
* хранение когнитивной памяти агента;
* выбор стратегии;
* оценку качества мышления агента.

---

### 23.2. Агент как внешний клиент

Для среды агент является внешним клиентом.

Минимальный цикл взаимодействия:

```text
Environment
     │
     │ observation
     ▼
   Agent
     │
     │ action
     ▼
Environment
     │
     │ consequence + new observation
     ▼
   Agent
```

Таким образом, среда не зависит от того, каким способом реализован агент.

К ней могут подключаться различные реализации:

```text
LLM без памяти
LLM с памятью
LLM с различными механизмами retrieval
алгоритмический агент
случайный агент
контрольный агент
```

Все они должны взаимодействовать со средой через один и тот же контракт.

---

### 23.3. Изоляция состояния

Состояние среды должно существовать независимо от состояния агента.

Среда хранит:

```text
world state
expedition state
transition history
seed
configuration
```

Агент хранит:

```text
internal state
memory
experience
retrieved experience
reasoning state
```

Эти два множества состояния не должны смешиваться.

Особенно важно не помещать память агента внутрь Environment Service.

---

### 23.4. Экспедиция как изолированный экземпляр состояния

Каждая экспедиция должна иметь собственный идентификатор и собственное состояние.

```text
Environment Service
│
├── Expedition 001
│     ├── S0
│     ├── S1
│     ├── S2
│     └── Sn
│
├── Expedition 002
│     ├── S0
│     ├── S1
│     └── ...
│
└── Expedition N
```

После завершения экспедиции её журнал должен становиться неизменяемой записью результата.

Создание новой экспедиции не должно зависеть от состояния предыдущей экспедиции, за исключением явно заданных экспериментом параметров.

---

### 23.5. Воспроизводимость

Каждая экспедиция должна однозначно определяться как минимум:

```text
environment_version
experiment_configuration
seed
initial_state
action_sequence
```

При одинаковых параметрах среда должна воспроизводить одинаковую последовательность переходов.

Версия среды должна сохраняться вместе с результатом эксперимента.

Это необходимо для возможности сравнивать результаты после изменения программной реализации.

---

### 23.6. Параллельное выполнение

Среда должна допускать независимый запуск нескольких экспедиций.

Например:

```text
Environment Service
│
├── Expedition A
├── Expedition B
├── Expedition C
├── Expedition D
└── ...
```

Параллельность не должна изменять поведение отдельной экспедиции.

Это позволит в дальнейшем запускать серии экспериментов с различными агентами, seed и конфигурациями.

---

### 23.7. Интерфейс взаимодействия

Конкретный протокол будет определён на следующем этапе.

Логически он должен обеспечивать как минимум операции:

```text
CREATE_EXPEDITION
OBSERVE
ACT
GET_STATE
GET_JOURNAL
FINISH_EXPEDITION
```

При этом внутреннее состояние среды не является частью общего интерфейса.

Агент получает только то представление состояния, которое определено моделью наблюдения.

---

### 23.8. Отсутствие визуального интерфейса

Графический интерфейс не является частью Environment Service.

Среда должна быть полностью работоспособной в headless-режиме.

Это позволяет использовать один и тот же сервис:

```text
Agent
  ↕
Environment API
  ↕
Experiment Storage
```

без участия человека.

Визуализация является внешним инструментом анализа и может подключаться к журналу эксперимента независимо от работы среды.

---

### 23.9. Аналитический контур

Аналитика должна быть отделена от исполнения среды.

```text
                Environment
                     │
                     ▼
                  Journal
                     │
          ┌──────────┼──────────┐
          ▼          ▼          ▼
       Analysis   Replay    Visualization
```

Это позволяет анализировать эксперимент после его завершения, не изменяя состояние среды и не вмешиваясь в ход экспедиции.

---

### 23.10. Принцип разделения

Физическая архитектура должна отражать экспериментальную гипотезу:

> **Среда предоставляет пространство возможностей. Агент осуществляет выбор. Опыт возникает из взаимодействия между ними.**

Поэтому Environment Service не должен становиться частью когнитивной системы.

В минимальной конфигурации эксперимент состоит из двух независимых процессов:

```text
┌─────────────────┐          ┌─────────────────┐
│      AGENT      │          │   ENVIRONMENT   │
│                 │          │                 │
│ perception      │◄────────►│ state           │
│ cognition       │          │ rules           │
│ memory          │          │ transitions     │
│ retrieval       │          │ generation      │
│ decision        │          │ journal         │
└─────────────────┘          └─────────────────┘
```

Именно это разделение должно сохраняться независимо от конкретной реализации и способа развёртывания.

---

## 24. Главная граница первого этапа

На первом этапе мы не пытаемся построить искусственное сознание.

Мы создаём минимальное пространство, в котором можно проверить более раннее и фундаментальное предположение:

> **может ли агент, взаимодействуя с ограниченной динамической средой, сформировать эмпирический опыт, сохранить его и использовать при последующем выборе.**

Если этот механизм не проявляется в минимальной среде, дальнейшее усложнение когнитивной архитектуры не имеет экспериментального основания.

Если проявляется — среда становится полем для следующего этапа исследования.
